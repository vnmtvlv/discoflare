# Discoflare 0.1.0

This is the first product-milestone release after the initial installer baseline.

## What's new

- Build versioned Gadgets from multiple Database Views, with explicit Bindings and Role access frozen into each published Version.
- Connect one App Domain and multiple Email Domains after a base workspace is already healthy on `workers.dev`.
- Create Mailboxes on a selected Email Domain. Managed installations provision one exact Cloudflare literal-address route per Mailbox instead of claiming a zone catch-all.
- Disconnect Mailboxes and managed domains with targeted cleanup that leaves unrelated zone-level Email Routing configuration alone.

## Deployment

- Guided first-run installation remains a free-plan-compatible base Worker with D1, R2, KV, core Durable Objects, Workers AI, Browser Run, and builtin invite-only authentication.
- Existing databases apply `0024_gadgets.sql` and `0025_multiple_email_domains.sql`. The latter preserves the existing Mailbox, Thread, and Message graph while allowing multiple Email Domains.
- The release manifest advertises `managed-domain-lifecycle-v1` for the matching discoflare.com Settings flow.
- App Domain and Email Domain choices are not part of the base installer request. They are post-install lifecycle operations.

## Security and privacy

- The broad Cloudflare OAuth credential remains encrypted in the private control plane and never enters a workspace Worker.
- A managed workspace receives a separate random Installation Control Credential that can only create or delete an exact mailbox route for that Installation. The control plane stores only its hash.
- Workspace content remains in the owner's Cloudflare account.

## Known limitations

- Email Domains can be connected only to the Primary Installation in a Cloudflare account.
- Disconnecting an Email Domain requires deleting its Mailboxes first.
- The control plane intentionally leaves shared zone-level Email Routing enabled when a domain or Installation is removed.
