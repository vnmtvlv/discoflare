# Discoflare 0.2.2

Discoflare Admin can recover a forgotten password with one-use recovery codes, and new workspaces can start without R2.

## Admin recovery codes

- Claiming an Admin shows ten recovery codes once, with a download and save step. Store them privately in a password manager or offline.
- Existing Admin owners can generate their first codes after updating, under **Account recovery**, by confirming their current password. Generating a replacement set invalidates previous codes.
- **Forgot your password?** accepts the Admin email, an unused code, and a new password. A successful reset consumes the code and signs out every previous session. Recovery runs entirely in the account-local Admin without discoflare.com or email delivery.
- If both password and codes are lost, the Cloudflare account operator can still set a new `ADMIN_CLAIM_TOKEN` and reclaim the Admin with its private setup link.

## Optional R2

- The Admin's **New workspace** form starts with files and backups disabled. R2 is no longer required for a text workspace.
- Without R2, attachments, uploaded avatars/icons, and full workspace backups are unavailable. The UI explains the limitation; file and backup APIs return an explicit disabled error. Incoming email retains its text and reports omitted attachments.
- To enable storage later, complete the R2 subscription setup in Cloudflare, then choose **Files and backups → Connect R2** on the workspace's Admin page. This attaches the workspace bucket without replacing its code, credentials, database or other bindings. Reload the workspace afterward.
- Existing workspaces keep their current R2 buckets during updates. Updates also preserve a workspace that has no R2 binding.

## Workspace sign-in

- Workspace owners can configure Google and LinkedIn sign-in alongside the existing providers in Workspace Settings. Provider secrets entered there are stored encrypted; environment credentials remain supported.
- Google requires an OAuth web application; LinkedIn requires OpenID Connect sign-in to be enabled for its application. Register the callback URL shown by the workspace before enabling a provider. Providers are unavailable until their credentials are configured.

## Updating

Update the account-local Admin to 0.2.2, then update its workspaces. Admin recovery tables are added automatically in Admin D1; existing owner credentials remain valid. The workspace update applies migration `0031_google_linkedin_auth.sql`, which adds Google/LinkedIn settings and expands the provider credential table while preserving existing credentials. Recovery itself adds only Admin-local tables.

R2 still requires Cloudflare's subscription checkout. Included usage and Cloudflare account limits apply; enabling R2 does not make additional usage free. No email-based Admin recovery, Hosted provisioning, or billing is introduced.
