# Discoflare 0.2.1

This patch hardens how the workspace and account-local Discoflare Admin are
documented and released. Workspace behavior is unchanged from 0.2.0.

## Improvements

- The repository instructions, architecture decision, deployment guidance, and
  release documentation now consistently describe one account-local
  Discoflare Admin per Cloudflare account. `discoflare.com` creates or
  reconnects the Admin without retaining a Cloudflare credential.
- The release contract now explicitly lists all six artifacts: the workspace
  Worker and assets, Admin Worker and assets, shared manifest, and versioned
  `@discoflare/admin-core` package.
- The manifest boundary is explicit: it pins and verifies both Worker payloads,
  while `admin-core` is a versioned companion asset in the same GitHub Release.
- Release builds and CI use Node.js 24.21.0 from `.node-version`.

## Release integrity

- Pushing a protected `v<version>` tag now builds and verifies a draft GitHub
  Release before a maintainer publishes it.
- The workflow verifies that the draft contains exactly the locally generated
  artifact set. Draft assets can be repaired before publication, while GitHub's
  native immutable-releases protection locks the tag and assets afterwards.
- Published versions are never repaired in place. A broken release is followed
  by a new patch version.

## Deployment

- There are no database migrations or new Cloudflare bindings in this release.
- Existing 0.2.0 workspaces and Admins can update normally. Independent source
  deployments do not need any configuration changes.
- Repository builds require the Node.js version pinned in `.node-version`.

## Known limitations

- GitHub release immutability applies to 0.2.1 and later; it does not
  retroactively lock the previously published 0.2.0 release.
