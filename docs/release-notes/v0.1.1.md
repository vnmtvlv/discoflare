# Discoflare 0.1.1

This release puts post-install Cloudflare infrastructure where workspace owners expect it: inside the workspace.

## What's new

- Connect one App Domain from **Workspace Settings → Cloudflare** by choosing a zone and entering a subdomain such as `inchi`.
- Connect multiple independent Email Domains from the same settings page, then create addresses in **Workspace Settings → Email**.
- Keep the base guided installation free-plan-compatible and independent from future domain choices.

## Fixes

- A subdomain label is now resolved inside the selected active Cloudflare zone instead of being rejected as an incomplete hostname.
- Discoflare Admin no longer presents App Domain and Email Domain as account-console configuration. It remains the place for base installation and private Owner setup recovery.

## Deployment

- There are no database migrations in this release.
- Existing managed workspaces can update normally from **Workspace Settings → Updates**.
- The workspace uses its Installation Control Credential for a fixed set of domain and mailbox operations. The broad Cloudflare OAuth credential remains encrypted in the private control plane and never enters the workspace Worker.

## Known limitations

- Disconnecting an Email Domain still requires deleting its Mailboxes first.
- Direct repository deployments without a managed Installation identity continue to configure domains through their own deployment workflow.
