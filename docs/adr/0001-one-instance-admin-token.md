# Use one account-owned token per managed installation

Status: Superseded by ADR 0002.

Managed Discoflare installations use one account-owned Instance Admin Token for self-updates, RealtimeKit, and Cloudflare email infrastructure instead of separate provider credentials. Cloudflare's public OAuth scope catalog does not expose Account API Tokens Write, so a guided installation finishes without this credential or either optional infrastructure integration. After creating the Owner, the operator opens Cloudflare settings on the installed workspace origin, follows a pre-filled account-token template, and pastes the value back there once. The workspace verifies it, writes it to its own Worker secret, enables RealtimeKit, and enables email when the Primary installation already has an explicitly selected Cloudflare zone. The token never passes through `discoflare.com`.

Cloudflare grants these operations at account or zone scope rather than at one Discoflare Worker, so multiple secrets would add lifecycle and recovery complexity without creating a reliable isolation boundary; deployments that need stronger isolation should use a dedicated Cloudflare account. Manual management retains no Instance Admin Token and requires fresh installer authorization for Cloudflare changes. Disconnecting Managed operation removes the secret and Huddles while preserving already configured email routing; the operator then revokes the disconnected account token in Cloudflare.
