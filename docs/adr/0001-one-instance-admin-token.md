# Use one account-owned token per managed installation

Managed Discoflare installations use one account-owned Instance Admin Token for self-updates, RealtimeKit, and Cloudflare email infrastructure instead of separate provider credentials. Cloudflare's public OAuth scope catalog does not expose Account API Tokens Write, so the guided installer cannot silently mint this credential: it opens a pre-filled account-token template, the operator creates the token in Cloudflare, and pastes its value back once. The installer verifies it, writes it to the instance's Worker secret, and retains no copy. Cloudflare grants these operations at account or zone scope rather than at one Discoflare Worker, so multiple secrets would add lifecycle and recovery complexity without creating a reliable isolation boundary; deployments that need stronger isolation should use a dedicated Cloudflare account. Manual management retains no Instance Admin Token and requires fresh installer authorization for Cloudflare changes.
